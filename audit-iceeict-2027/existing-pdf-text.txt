Abstract—We study a physics-informed neural network (PINN)
approximation of one nearly closed orbit of the Lorenz–1960
three-state system on t ∈[0, 13.26446]. A single network trained
on the full interval gives a combined state root-mean-square
error (RMSE) of 2.237 against a numerical reference in the saved
experiment. We instead divide the interval into 27 windows. Each
window has its own network and an initial state fixed to the
previous window’s predicted endpoint. Within a window, Adam
minimizes a time-weighted residual through four causal stages;
L-BFGS then minimizes the ordinary residual. A numerical
reference is monitored during training but does not control
optimization or stopping. In the reported single-seed run, the
windowed model gives a combined RMSE of 6.97 × 10−5 on
13,265 evaluation times and a dense-grid residual mean square
of 1.87 × 10−7. The two monitored quadratic invariants have
maximum relative drifts of 2.60 × 10−4 and 1.68 × 10−4.
The full-interval and windowed runs also differ in parameter
count, sampling, and optimizer schedule. Their contrast therefore
describes these configurations; it does not isolate the effect of
causal weighting.

I. INTRODUCTION
The Lorenz–1960 model is a three-state nonlinear ordinary
differential equation (ODE) derived from a reduced flow model
[1]. Its initial-value problem offers a clear test of whether a
learned continuous-time function follows a prescribed trajec-
tory over an extended interval. Numerical integration supplies
a reference trajectory. A physics-informed neural network
(PINN) offers a different representation: a differentiable func-
tion trained by the ODE residual rather than by solution
samples [2].
Training one PINN on a long interval can be difficult. Its
loss couples early and late times, although the state at a late
time depends on the preceding trajectory. Wang et al. proposed
time-dependent residual weights to address this ordering in
PINN training [3]. A hard trial solution can also satisfy an
initial condition by construction [4]. We use both ideas, with
a separate network for each of 27 consecutive time windows.
The endpoint predicted in one window fixes the initial state
of the next. The weights of a finished network initialize its
successor.
This paper reports one implementation and its saved results
on [0, 13.26446], an interval that nearly completes an orbit
for the selected initial state. We give the exact training
objective and window handoff, then compare the result with
a saved single-network run on the same initial-value problem.
We also check the state error, ODE residual, and conserved
quadratic forms. The comparison is descriptive because several
configuration choices change together.

B. PINNs for Time-Dependent Problems
The original PINN formulation uses derivatives of a net-
work output in the governing-equation residual [2]. Lagaris et
al. gave a trial-function construction that satisfies prescribed
conditions exactly [4]. Wang et al. introduced causal residual
weights for time-dependent PINNs [3]. Penwarden et al.
studied causal sweeping with temporal decomposition [5].
Our separate networks, state handoff, and optimizer sequence
define the particular configuration tested here; we do not claim
these building blocks as new.
III. WINDOWED PINN METHOD AND IMPLEMENTATION
A. Model Construction and Time Routing
The entry point run_causal.py builds a validated
Config; sweep_config assigns its run directory, and
run_one calls train. Training sets NumPy and PyTorch
seed 0, selects CUDA when available, and constructs the

model in float64. WindowedPINN stores K = 27 inde-
pendent PINN modules, one for each equal interval Wk =
[tk, tk+1]. Each maps one time input to three outputs through
four width-60 tanh layers and a linear output. We denote its
raw output by Nk(t; θk). Linear weights use Xavier-uniform
initialization and biases start at zero. One module has 11,283
trainable parameters; the full model has 304,641. The for-
ward pass routes each time with torch.bucketize(...,
right=True). Thus a shared edge belongs to the incoming
window when the piecewise model is evaluated.

D. Optimizer Sequence and Saved State
Figure 1 gives the flow; Algorithm 1 gives its order.
train_windows creates a fresh Adam optimizer and
StepLR scheduler for each window. Adam starts at 10−3;
the scheduler multiplies its rate by 0.9 every 1,000 up-
dates and continues across that window’s four stages ϵ =
(0.01, 0.1, 1, 10). Each stage has a 4,000-update cap. After
an Adam update, the code recomputes weights at the updated
parameters when the saved minimum weight exceeds 0.99 or
the stage reaches its cap. It advances only if this post-update
minimum exceeds 0.99; otherwise it advances at the cap and
records failure to meet the threshold. L-BFGS then minimizes
the unweighted residual mean for up to 1,000 iterations. It uses
history size 50, a strong-Wolfe line search, and float64 gradient
and change tolerances of 10−12 and 10−16. The recorded
number of L-BFGS closure calls is not the iteration count.
After each window, the code saves window_XX.pt, trans-
fers the endpoint state, and writes an atomic progress.pt.
The resume file contains the exact configuration, all module
states, training history, next window, and PyTorch, NumPy,
and CUDA random states. A resume with a different configu-
ration is rejected. The run also writes stage status and residual
snapshots. DOP853 values are recorded at configured evalua-
tion intervals as diagnostics; they do not enter the loss, gradi-
ent, or stopping test. After training, collect_artifacts
evaluates the final piecewise model and its residual on the
collocation and dense grids. run_summary computes error
and invariant measures from these arrays. The reported full-
domain residual is a new evaluation, not the last window’s
training objective.

VI. DISCUSSION AND LIMITATIONS
The hard trial form fixes each window’s start value, and the
endpoint rule gives value continuity. The run’s low errors do
not isolate which training choice mattered: no same-budget,
same-grid windowed run without causal weights was saved.
The experiment covers one initial state, one coefficient
choice, and one seed. We cannot infer reliability across seeds
or other trajectories. Each new window starts from a predicted,
rather than exact, state, so errors can pass through the handoff.
The trial form also leaves derivative agreement at joints
unconstrained. The post-update causal threshold was missed

PAGE 5
in two stages, and its accumulated loss changes with the
number of time points. These facts matter when transferring
the settings to another grid or interval. A controlled study
would fix the grid, model capacity, and optimizer budget while
changing one training choice at a time, then repeat across
seeds.
VII. CONCLUSION
On the nearly closed Lorenz–1960 orbit [0, 13.26446], the
saved 27-window run gives a combined state RMSE of 6.97×
10−5 against DOP853. A separately configured single-network
run gives RMSE 2.237. This contrast supports the windowed
configuration for this test; matched ablations and repeated runs
are needed to assess its individual design choices.
